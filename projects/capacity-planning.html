The frontend is statically exported with output: 'export'. Plain Django views provide the backend without DRF; Docker packages the system for AWS ECS Fargate, with WhiteNoise serving the SPA assets.

Normalized operational model

The MySQL 8.4 model uses 38 normalized tables to keep people, branches, roles, availability, shifts, requests, permissions, and outcomes transactional and auditable.

  • Shift: master templates and reusable roster intent.
  • StagingShift: live calendar rows replicated six months forward.
  • Protected statuses—vacation, half-day, bank holiday, paid leave, and temporary—are preserved during replication rather than overwritten by a template refresh.

Decision-support engines

M3 mobile workforce optimizer

  • Dynamic-programming core with swap refinement.
  • Accounts for travel allowances, reach maps, and country-scoped runs.
  • Turns a broad staffing search into a controlled, explainable planning run.

Vacation-cover recommender

  • Loss-minimization model ranks cover candidates against operational impact.
  • DecisionOutcome grades recommendations against Redash actuals using a ±25€ acceptance band.

Target calibration

Formula pricing calibrates a configured branch roster against role targets instead of treating headcount as a single number.

  • Working-day targets.
  • 20- or 30-minute slot lengths.
  • Distinct-person headcount separated from team composition.

The result is a measurable bridge between the roster a branch needs and the schedule the system generates.

Authentication and delivery

Google OAuth establishes identity; Django issues an HS256 JWT stored in localStorage for the application session. The deployment path keeps static frontend delivery and backend operations independently observable.
